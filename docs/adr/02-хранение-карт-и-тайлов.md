## ADR-02. Хранение карт и тайлов

| Поле    | Значение                                                     |
| ------- | ------------------------------------------------------------ |
| Статус  | принят                                                       |
| Дата    | 2026-11-10                                                   |

### Контекст

Симулятор радиолокационной системы использует двумерную декартову систему координат. Все события моделируются на плоскости. Требуется единое решение для размещения растровых изображений тайлов и их метаданных.

### Альтернативы

| Критерий сравнения              | Статические файлы (`zoom/x/y.png`)   | PostgreSQL (метаданные) + MinIO (тайлы)   | MBTiles (SQLite) / PMTiles                      |
| ------------------------------- | ------------------------------------ | ----------------------------------------- | ----------------------------------------------- |
| Размещение растра               | Файловое хранение                    | объекты в бакете `maps`                   | архив-файл                                      |
| Размещение метаданных           | Файловое хранение в формате TileJSON | таблицы PostgreSQL                        | архив-файл                                      |
| Управление, поиск по метаданным | Ограничено                           | Высокое, SQL DML                          | Ограничено. запросы «по содержимому» невозможны |
| Новые зависимости               | нет                                  | нет                                       | нужен тайл-сервер                               |
| Версионирование набора          | контракты файловой системы           | Гибкое: явное указание в таблице          | новая версия - новый архив                      |
| Масштабирование                 | Низкое                               | Отличное                                  | Среднее                                         |
| Обновление данных               | Ручная работа с файлами              | Полная сборка новой версии (S3 API + SQL) | Пересборка архива PMTiles                       |
| Итог                            | —                                    | принят                                    | —                                               |

### Решение

Принята связка **PostgreSQL (метаданные тайла) + MinIO (тайлы)**: растр и метаданные размещаются одним решением, а не двумя независимыми выборами.

Растровые изображения тайлов хранятся в MinIO в бакете `maps` по заданному ключу. Чтение может быть организовано через обратный прокси с возможностью кэширования по ключу объекта. Ключ тайла клиент получает из его метаданных.

### Обоснование

- MinIO уже используется для снимков, PostgreSQL — для доменных данных: новые сервисы и зависимости не появляются.
- Растр и метаданные разделены: большие неизменяемые файлы не раздувают базу данных, а метаданные остаются структурированными и доступными для выборок по набору, версии и адресу `zoom`/`x`/`y`.
- Размер тайла в пикселях и формат растра одинаковы для всех тайлов версии, поэтому хранятся в `map_set` одной строкой, а не повторяются в `map_tile`.
- MinIO масштабируется независимо от базы данных и одинаково доступен всем репликам Kubernetes.
### Последствия

- Плюс: переиспользование MinIO и PostgreSQL, запросы к метаданным без чтения растра, независимое масштабирование хранилища, явная метамодель.
- Минус: два хранилища в одном решении требуют согласованной записи объектов и строк `map_tile` при загрузке набора.
